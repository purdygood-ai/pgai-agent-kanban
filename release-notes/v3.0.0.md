# pgai-agent-kanban v3.0.0

**Release Date:** 2026-10-28

Changes since v2.42.0.

This release changes how the kanban stops. It no longer parks a project and waits for a human when a release is weak, a bug needs an answer, or a provider error interrupts an agent. A weak release ships with its status written in its notes. A question goes into a per-project operator inbox and the chain continues around it. An interrupted agent is retried on a timed ladder. The chain stops on its own only when continuing would be worse than stopping: a runaway, or a failure that would corrupt the repository. OVERWATCH now does the mechanical part of the operator's job through a fixed table of verbs, with no model in the loop. Forty-four internal releases are folded into this one.

## Features

- **Releases ship by default.** The three ship-policy triggers that used to halt a project now ship the release with a status of NON-FUNCTIONAL or KNOWN-BUGS, record an auto-ship event and file a bug. Set `ship_posture = matrix` in `kanban.cfg` or a project's `project.cfg` to restore the halts. A lane that pushes to a remote also needs `ship_posture_confirm_remote = true`, otherwise it keeps the matrix behaviour.
- **Verification that cannot run is retried once, then the release ships anyway.** A blocked or missing tester report requeues verification. If it fails again the release ships NON-FUNCTIONAL and writes an inbox entry. A release run that arrives while the requeued verification is still pending waits for it instead of shipping unverified.
- **Mechanical release failures resolve without a halt.** A squash conflict cancels and rebundles the release candidate and names the conflicting paths in the inbox. A refused push ships locally and records a push-lag event. The push-lag check pushes main and the tag once the remote accepts them, and deletes the leftover release-candidate branch it recorded. A tag already on the remote writes an inbox entry and changes nothing locally. The hook, squash-pollution, fidelity and version gates still halt, and now write their reason to the inbox as well.
- **A blocked task parks only itself.** Independent tasks in the same batch keep running, as do other projects. Only tasks that name the blocked one as a prerequisite wait.
- **Provider errors retry instead of parking.** A run cut short by a transient provider error (rate limit, overload, a safeguard abort) is recorded with its own reason code, matched against one shared signature table, whether the wake saw the error or the agent reported the block itself. The task requeues on a timed ladder up to `[wake] transient_retry_cap` before it reaches the inbox. A blocked planner, tester or release task, which the chain cannot continue without, requeues on a ladder of its own before any inbox entry. Ladder retries do not count as repeats for the runaway detector.
- **OVERWATCH decision wake.** The hourly sweep runs a decision wake for every project. Anything it can resolve with an operator verb, it resolves. Anything that needs a human answer but does not endanger the pipeline goes to the inbox. Runaway detection stops a project when releases, release-candidate cycles, identical blocks or inbox entries exceed configured rates in a window. Design decisions, version changes, provider changes, operator halts and code edits stay human-only.
- **Operator inbox.** One file per project holds the open questions and their answers. `scripts/inbox.sh --project <name> list | answer --id <ID> --answer <text> | close --id <ID>`. The dashboard shows one line per entry and the newest question on the attention pane.
- **Bug convergence.** A bug that needs an operator answer is marked `needs-operator` and excluded from bundling, ship-time promotion and tester re-filing until the inbox entry is answered. Intake refuses a draft that reports the same defect as an open bug and names that bug. A loop detector closes remaining duplicates. Bounded deferral opens a bugfix bundle when deferred bugs grow too many or too old, even while requirements are queued. Ride-along lets the planner attach a capped number of deferred bugs to a requirement release.
- **Per-project test runners.** Each project names its own targeted and pre-merge test commands under `[testing]` in `project.cfg`. The planner writes exactly those commands into ticket acceptance criteria, whatever shape the runner's option list takes. A project with none set gets no runner criteria.
- **Reliability streaks.** One ledger records every block with its class, cause and reason. Each project shows two streaks, hands-off and clean, as releases and hours, on the metrics pane, in `metrics-report.sh --reliability` and over a read-only REST route. `scripts/reliability-backfill.sh` reconstructs the ledger from existing evidence.
- **Task-liveness records.** Every dispatched task leaves a record naming its process, so the kanban can tell a live task from a dead one. Records are removed when the task ends and leftovers are swept by cleanup.
- **Release lifecycle hooks on every project.** The pre-squash, pre-tag and post-tag hook points resolve through a config key, a kanban-side hooks folder, or a file travelling in the repository, in that order. A failing hook now stops the release with an inbox entry rather than a bare halt.
- **Template drift notice.** Install and upgrade report when the project README template changed since a project was seeded and print the diff command.

## Fixes

Defects present in v2.42.0 and fixed in this release:

- **Intake.** A bug number that belonged only to an archived bug is no longer reused. The remedy for a file name that is not bare now names the right fix, in the command and in the API.
- **Project registry.** The bash and Python readers agree on headers with trailing spaces, Windows line endings or a trailing comment, on a project registered twice, on a section whose name the registry rejects (its priority no longer bleeds into the project above it) and on a `branch_prefix` carrying a comment. The project-name rule is defined once, so a name the registry accepts is a name the wake will wake and the release can open. OVERWATCH checks no longer print a syntax error on an empty registry. The readers no longer need the palette file to be present.
- **Dashboard.** The queue pane renders the queue instead of always reporting it empty. The next-firing line prints minutes, not seconds. The attention and pipeline panes no longer count the current directory when a tasks path is empty. The REST board and the dashboard agree on which requirements are released.
- **Release.** Requirement lookup by version is case-insensitive in both places that do it. Hook remedies quote paths and handle a hook committed as a symlink. The executable-bits check no longer skips paths with spaces, symlinks or submodule entries. The quarantine check reports a failing helper instead of aborting silently. The bundle migration honours the tag prefix. The release script's help names every trigger a decide-only run can report. After a local-only release the narration no longer points at a push step that contacts no remote.
- **Generated release notes.** Bugs filed through intake carry their severity in the skipped-bugs table. A summary is no longer cut at a period inside a backticked command. Known Issues and Documentation no longer print `None` beside real entries. Commit hashes and branch names quoted from bug reports are scrubbed before they reach the notes.
- **Verification.** The gated runners write their findings, coverage and census files per run, so a tester certifying one release candidate never reads a file an earlier run left behind. The stale-literal check skips generated API baselines instead of searching the tree for every string in them.
- **Processes.** A process an agent started during a task no longer survives the task. A unit test can no longer push through the git guard from inside an agent wake.
- **Remedies and messages.** Codex preflight no longer passes a model whose check exited non-zero with empty output. The refusal ledger no longer doubles its prefix. The bare-temp cleanliness check no longer blames a sibling project. Dev-tree, import-project and create-project messages name commands that run as printed. The deferral campaign file names the scripts where an installed kanban has them. A migration script exits 0 on success as its help says.

## Reliability

- One markdown section reader, one configuration resolver, one temp-root resolver, one registry reader and one provider-error signature table behind every caller, each guarded by a lint that fails when a copy appears.
- No inline Python in bash: the remaining blocks moved into modules and the allowlist is empty.
- New lints in the pre-merge gate: engine-size ceiling over every engine module, duplicate definitions, test anti-patterns, documentation key parity, governance byte budgets per role, section-parser copies, documentation command truth.
- Timing-sensitive lock tests tolerate host load.
- Task-liveness and lock records make a stale lock distinguishable from a working one.

## Documentation

- Every role file and the governance text were rewritten to say what the code does: releases ship by default, verification is requeued, bugs go through intake, provider errors retry, and each step says whether it applies to the kanban's own repository or to a managed project with its own runners.
- Operations guide: HALT scopes, the inbox, deferral posture and bounds, release lifecycle hooks, the per-project `[testing]` keys and the acceptance policy they drive, the cleanup script's steps, the crontab convention through the wake batch, the pseudocron example, the per-release rollup, the dashboard log snippet.
- OVERWATCH guide: the reason-code table names every writer of each block record, the retry ladders and the runaway detector's counting rule.
- The release reference and the verification reference restate the same facts as the role files.
- A project README lists the rules the pre-merge gate enforces.

## Operator-facing changes

- `scripts/inbox.sh` is new. `close.sh` can close a `needs-operator` item as `wont-do` or `duplicate`.
- `scripts/reliability-backfill.sh` is new. `metrics-report.sh --reliability [--project P]` prints the streaks.
- `scripts/cm/release.sh --decide-only` reports which of triggers 2, 3 or 8 a halt would come from.
- The crontab template fires agents in pipeline order: PM, CODER, WRITER, TESTER, CM at 0, 12, 24, 36 and 48 seconds past the minute. The daily OVERWATCH model wake is gone; the hourly `overwatch-sweep.sh` at minute 30 runs the decision wake.
- A root `HALT` stops every project; a project `HALT` stops one. A `HALT-AFTER` finishes the release in flight and then halts; `halt_after_auto_resume = true` lets OVERWATCH clear that halt once the drain completes.
- The cleanup script deletes leftover task-liveness records as its Step 2b.
- The tester deposits bugs through intake, so the same-defect check runs on every filing.
- The board and dashboard show `needs-operator` in its own colour, mark a carried item, and split the open-bug count into open, deferred and needs-operator.

## Breaking changes / upgrade notes

- Upgrade with `scripts/upgrade.sh v3.0.0 --force --add-claude-agents --add-codex-agents`, then reinstall the crontab so the new order takes effect: `scripts/install-crontab.sh --wake-tier <small|medium|large> --yes`.
- **Two defaults change, and the migration rewrites them in `kanban.cfg`.** `[wake] stop_on_blocked` becomes `false`; set `stop_on_blocked = true` to restore stopping a project's batch on the first blocked task. `[release] ship_posture` becomes `always`; set `ship_posture = matrix` to restore the halts. Values a project sets in its own `project.cfg` are left alone.
- **Push lanes.** A project with `push_to_remote = true` keeps the matrix behaviour until its `project.cfg` sets `ship_posture_confirm_remote = true`.
- **One behaviour change with no opt-in.** A bug or priority still `running` that no bundle lists becomes `needs-operator` on the next discovery pass, with the carry reason recorded.
- **Retired key.** `[providers] initial` is no longer read. The loader notes the line once and asks you to delete it.
- **New keys, all optional.** `[release] deferred_max_age_days`, `deferred_max_count`, `bundle_mixing` (`separate` or `ride-along`), `ride_along_max`. `[overwatch] runaway_releases_per_hour`, `runaway_rc_cycles_per_day`, `runaway_reason_repeats`, `runaway_inbox_entries_per_day`, `halt_after_auto_resume`. `[governance] budget_bytes_<role>` example values are raised for the larger role files. In `project.cfg`: `[testing] targeted_test_command` and `pre_merge_command`; the migration seeds the kanban's own values into the self-build project, whatever that project is named, and every other project sets its own or gets no runner criteria.
- **Removed Python readers.** `lib/md_fields.section_body` and `cm/read_state_field.read_state_section` are gone; call `pgai_agent_kanban.task_status.read_section`.
- **New runtime directory.** `locks/task-liveness/` holds one record per dispatched task. Nothing to configure.
- **Version ceiling.** `project.cfg` ships with `max_major = 0`, which stops the chain from minting a major release on its own. A project whose next versions are 3.x needs `max_major = 3`, set with `scripts/set-version-ceiling.sh --project <name> --major 3`.
