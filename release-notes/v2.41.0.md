# pgai-agent-kanban v2.41.0

**Release Date:** 2026-10-15

Changes since v2.4.0.

A software shop in a box that you can start and walk away from. Between the two public releases the kanban built about 178 releases of itself and fixed about 700 bug reports, each one planned, implemented, verified and shipped by its own agent chain.

## Features
- **"Why isn't it moving?" in one line.** `why.sh` prints one verdict per project (RUNNING, BLOCKED, HALTED, IDLE or STUCK-LOCK) with the cause and a runnable fix. `--details` adds lock holders, queues and posture.
- **A full operator API.** Every operator verb has a REST twin: halt, halt-after, defer, wake-now, intake, cancel and unwind RC, deep-verify, add and remove project, archive. The CLI and the API call the same code. Loopback-only, with a versioned interface contract.
- **Ship by default, with a record.** HALT means "shipping would make things worse", not "the tester found something". Findings ship as known issues and become the next RC's bugs. Each project has a ship posture (`matrix` or `always`); `cm/release.sh --decide-only` previews the decision and `--force --reason` overrides it with a recorded reason.
- **Low-severity bugs wait their turn.** Bugs at or below `deferred_bug_level` do not set the release tempo; they ride along when a more serious bug opens an RC.
- **OVERWATCH clears blocks itself.** Blocked tasks carry a structured block record. OVERWATCH resolves the mechanical cases (timeouts, provider refusals, stale worktrees, merge-only gates) and writes a short diagnosis for the rest.
- **Dashboard v2.** Fifteen windows plus one per project: an operator window with a shell, a schedule window with per-agent firings, metrics with time spent blocked, and a human-review window.
- **Containers you can leave running.** `docker/build.sh <flavor>` builds the debian, rocky9 or claude-abliterated image (a custom Claude build for local LLMs). `container-up.sh`, `container-down.sh` (soft stop) and `container-status.sh` run the kanban detached in one named container.
- **Finished work archives itself.** After each release, finished items beyond the newest 55 per category move to `archive/<project>/`, logged and restorable with `archive.sh --restore`.

## Fixes
- REST routes that take a path are confined to the kanban root, including encoded, absolute and leading-dash inputs. `add-project` refuses names that would escape the projects directory.
- Stale locks are reaped safely, every lock records its holder and reason, and `release-locks.sh` frees stuck ones.
- A task that stops making progress is flagged instead of cycling forever. A burst of blocks no longer freezes a project indefinitely.
- Claude usage-limit messages pause the fleet instead of burning retries.
- Help text, docs and printed remedies name scripts and flags that exist.
- Leaked test processes and listeners are cleaned up after test runs.

## Reliability
- Faster release candidates: coders run only the tests for the files they changed plus a quick pre-merge check; the tester runs the full suites once per RC, in parallel.
- Container cold builds moved to an on-demand or weekly deep-verify lane, recorded in a per-project ledger and checked before promotion.
- The dashboard redraws panes only while they are visible; the status line renders once every 5 seconds instead of costing most of a core per terminal.
- A protected `claude-env` file holds provider settings and survives upgrades; each wake logs the CLI version and model.

## Documentation
- Agents follow a four-layer instruction stack: kanban-wide rules, the role, the project's README, the task. Agents work on the git repository, never the live install.
- Shipped docs and comments describe behaviour, not history, and are kept short. Nothing in the tree is specific to any project the kanban has built; four demo projects remain as teaching material.
- Every configuration key is scaffolded in the example files with its default and a short description.

## Operator-facing changes
- New commands: `why.sh`, `release-locks.sh`, `defer.sh` / `undefer.sh`, `archive.sh`, `deep-verify.sh`, `container-up.sh` / `container-down.sh` / `container-status.sh`, and `docker/build.sh`.
- Rejected intake files are quarantined in `projects/<name>/rejected/`; `list-rejected.sh` and `recover-rejected.sh` read that location, and `recover-rejected.sh --rename` accepts a plain file name only.

## Breaking changes / upgrade notes
- Upgrade with `upgrade.sh v2.41.0` (or no argument for the newest tag), then re-deploy the agent wrappers with `--add-claude-agents` (and `--add-codex-agents` if you use Codex). State is preserved; upgrades are forward-only.
- New `kanban.cfg` sections and keys, all with defaults in `kanban.cfg_example`:
  - `[release]`: `ship_posture`, `deferred_bugs`, `deferred_bug_level`, `defer_piggyback`, `deep_verify`, `container_images`
  - `[wake]`: `block_hold_cap`, `block_storm_window`, `lock_starvation_firings`, `lock_wait_seconds`, `model_preflight_timeout_seconds`, `model_preflight_ttl_seconds`, `systemic_block_reasons`, `usage_limit_pause_seconds`, `zero_progress_cap`
  - `[overwatch]`: `block_triage`, `requeue_budget`, `leaked_listener_min_age_seconds`
  - `[testing]`: `workers`, `coverage`, `pre_merge_affected_cap`
  - `[archive]`: `archive_count`
  - `[docker]`: `container_name`, `image`, `container_stop_timeout_seconds`
  - `[governance]`: `budget_bytes_<role>` for each role
  - `[dashboard]`: refresh, layout and colour keys
  - `[api]`: `shell_out_timeout_seconds`
  - `[locks]`: `stale_lock_reap_after_wake_periods`
- Removed keys: `[chain] agent_lock_timeout_seconds` and `[providers] initial`.
- The per-project template is `team/config/project.cfg_example`; the root `project.cfg_example` points to it.
- Real configuration files (`kanban.cfg`, `project.cfg`, `projects.cfg`, `secrets`, `shell-env`, `claude-env`, pseudocron settings, keys) are ignored by git; only the `*_example` templates are tracked.
