# pgai-agent-kanban v2.42.0

**Release Date:** 2026-10-15

Changes since v2.41.0.

A maintenance release: the fixes from the first day of v2.41.0 in production. No new features and no configuration changes.

## Features
None.

## Fixes
- **The CHANGELOG is rendered only when a release ships.** It is no longer a committed file checked byte-for-byte by the test suites, so editing a release-notes file cannot turn a build red, and public Known Issue IDs are assigned exactly once, when the release ships.
- **A no-argument upgrade can no longer downgrade.** The forward-only check runs whether or not a version is given.
- **Bug intake claims its number atomically.** Two filings in the same minute get different numbers, a draft whose number is taken is renumbered with its title and ID lines rewritten, a file whose name breaks the ledger rule is refused with the correct remedy, and a refused file's number is never handed out again.
- **Deep-verify records the truth about cold-lane runs.** A run with no container engine is no longer recorded as "built", a run where every image built no longer lists a podman skip, and the "could not attempt" verdict is described consistently everywhere.
- **Release dates are read from one line.** The changelog tools accept only `**Release Date:**`, warn instead of printing "unknown" silently, and sort versions with the shared semver helper.
- **Help output in 41 scripts** no longer depends on a hand-counted header slice.
- **Crontab backups** written on install and upgrade are pruned instead of accumulating forever.

## Reliability
- Tests no longer leak tmux socket files into `/tmp/tmux-<uid>/`.
- Timing-sensitive tests (lock override, skip gate, dashboard arm) tolerate host load instead of failing under it.
- Stale prose about a changelog freshness gate and a hash-seed rationale that no longer applied are gone.

## Documentation
- The dashboard has 14 fixed windows plus one drill window per registered project; the docs said 15.
- The operations guide uses illustrative values instead of this project's internal history.
- The v2.41.0 notes state the right count: 229 internal releases between the two public releases.
- The intake section of the operator commands reference and the test guide describe the atomic numbering.
- A doc path citation and a missing docstring fixed.

## Operator-facing changes
- **The tester files bugs only.** It no longer files priorities or requirements. Enhancements, design changes and features the code was never asked for go in the verification report's `## Suggestions` section for the operator to read; nothing there is filed.
- **Rate the behaviour, not the test.** A test that fails for a cause inside the test itself (timing, host load, environment) is rated low, whatever colour the suite turned.

## Breaking changes / upgrade notes
- None. No configuration keys added, renamed or removed. Upgrade with `scripts/upgrade.sh v2.42.0 --force --add-claude-agents --add-codex-agents`.
