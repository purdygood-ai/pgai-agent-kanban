# pgai-agent-kanban v3.5.0

**Release Date:** 2026-11-07

Changes since v3.0.0.

This release supersedes v3.0.0. It reworks the operator window of the dashboard, ships operator skills for the Claude Code and Codex CLIs with a verb that installs them, puts a time limit on every release hook and every OVERWATCH verb, stops the kanban from discarding an agent's committed work, moves the last environment-only knobs into `kanban.cfg`, rewrites the Python package to Python 3.12 idioms, makes the kanban independent of a project's git checkout at run time, and fixes the process leaks, remote-contact paths, configuration-loading and log-format defects found while running v3.0.x in production. Forty internal releases are folded into this one.

## Features

- **Operator window: workbench pane.** Window 1 now carries a second, tall interactive shell on the far right, beside the board and the command line. Its width is `[dashboard] operator_workbench_pct` (percent of the window, default 40; `0` removes it). When the window is narrower than `operator_workbench_min_cols` (default 160), or a board column would get fewer than 15 columns beside it, the workbench is left out; a client that attaches from a narrower terminal, or a resize, moves it to its own window named `workbench` until the window is wide enough again.
- **Operator window: one AGENTS column.** By default the board shows BUGS, PRIORITIES, REQUIREMENTS and one AGENTS column listing every PM, CODER, WRITER, TESTER and CM task, newest first per project. `[dashboard] operator_board_agents = split` restores the five role columns. The visibility window keeps its eight columns either way.
- **Operator skills.** The repository ships one skill per assistant CLI, staged under `skills/claude/pgai-agent-kanban/` and `skills/codex/pgai-agent-kanban/` in the kanban root. `scripts/install-skills.sh` copies every staged skill into the Claude Code and Codex skill homes; `--list` shows each skill as `new`, `same`, `changed` or `invalid` per provider, `--dry-run` prints the plan, `--force` overwrites a changed copy, `--dir` and `--provider` install your own skills from another directory. Install removes nothing and skips a provider whose CLI is not on `PATH`. `GET /skills` lists the staging directory over REST.
- **Reset keeps unmerged work.** `scripts/reset.sh` on a task whose feature branch holds commits no other ref reaches now keeps the branch and the progress log, prints the tip and commit count, and marks the task to resume from that branch on its next dispatch. `--discard-branch` deletes the branch instead, warning how many commits it drops. `--force` alone never discards a branch. The wake's stale-active sweep keeps an orphaned task's branch the same way instead of force-deleting it.
- **Release hooks are bounded.** Every pre-squash, pre-tag and post-tag hook runs in its own process group under `[release] hook_timeout_seconds` (default 900). Past the limit the whole group, including anything the hook forked, gets SIGTERM and then SIGKILL after 5 seconds, and the hook counts as failed.
- **OVERWATCH verbs are bounded.** The cancel, unwind and release verbs the decision wake runs are limited by `[overwatch] verb_timeout_seconds` (default 3600) in their own process group; a verb that overruns is recorded as failed and the wake continues.
- **Six runtime knobs moved into `kanban.cfg`.** `[discovery] settle_seconds` and `reject_threshold`, `[cleanup] task_retention_days`, `[verify] deep_verify_freshness_window_days`, `[dashboard] status_max_width` and `arm_timeout_seconds`. The matching `PGAI_*` environment variables still win when set.
- **Planner ticket sizing.** Hygiene ride-alongs carried on a bug bundle are grouped by area into tickets of at most four items each, however many tickets that takes, instead of being packed into at most two tickets. A ticket is one agent session with one time budget; small tickets finish, show on the board and verify on their own.
- **Entry scripts work through a symlink.** Every operator script under `scripts/` finds its library directory from the resolved script path, so a symlink to it on your `PATH` runs like the real file.
- **The last-released version survives a missing tag.** When a project's dev tree holds no release tag carrying the project's branch prefix, the resolver answers from `release-state.md`'s `## Last Released` instead of `v0.0.0`. Before, deleting the tag made the board show every finished requirement as unreleased and would have numbered the next bundle from `v0.0.0`.

## Fixes

Defects present in v3.0.0 and fixed in this release:

- **Dashboard.** The board builder sizes its columns against the window a client is attached to, not the 220-column default the detached session is created at, so a 120-column terminal no longer gets 1-column BUGS, PRIORITIES and REQUIREMENTS columns. No board column is squeezed below 15 characters when a workbench is built or in `split` mode on a narrow window. `create.sh --session <name>` creates the session under that name even when `kanban.cfg` is present. `[dashboard] rows_per_column` is honoured, and every default now says 21. The two interactive shells open clean instead of showing the commands the dashboard typed into them at startup.
- **Release.** `scripts/cm/release.sh` invoked by a relative path from the kanban root no longer fails at the pre-squash hook step. A hook that ignores SIGTERM is killed after the documented 5 seconds instead of blocking the release while it holds the output pipe. Hooks now run with a timeout and in a process group, so a hanging hook or a forked daemon no longer stalls the release task or outlives it.
- **Wake and task budgets.** A wake started with the task budget unset ran tasks with no ceiling; the fallback to "no limit" is gone from the driver and the libraries. `[wake] max_runtime_seconds = 0` means "no batch bound" everywhere, instead of ending every batch before its first task. An interrupted gated-suite run now kills pytest grandchildren, not only direct children.
- **Project configuration loading.** When one wake iterates several projects and a later project's configuration fails to load, the earlier project's values (its dev tree path and temp directory among them) no longer stay in effect for the later project. Loading a project from a legacy `PROJECT.cfg` no longer keeps earlier values for fields the file does not set, no longer exports a multi-line list of shell variable names into every process the caller starts, and a line in that file that fails under `set -e` no longer returns success with every field unset.
- **Bug convergence.** A `needs-operator` bug whose inbox question was answered is no longer re-raised with the same question, and set `needs-operator` again, by the next bugfix bundle's planner. Every OVERWATCH check that files a bug deposits it through intake, so the same-defect check runs on every filing. A bundle carrying many hygiene ride-alongs no longer decomposes into one coding ticket too large to finish inside the task budget.
- **Project import.** `import-project.sh` keeps the final project name in the registration block it prints, drops a rejected-name section even when a later header passes, no longer overwrites keys of a different project already registered when run with `--register`, handles a legacy registration line against a legacy registry, and no longer appends a foreign section header inside the kept project section. The project-name rule is applied from its one definition.
- **Atomic state writes.** The per-release-candidate state file, the HALT-AFTER sentinel, the discovery settle and reject state, and a task status rewritten by the won't-do verb go through the atomic writer every other status change uses, so a reader never sees a truncated file.
- **Processes and traps.** EXIT traps installed by the event band, lock provenance and the OVERWATCH protocol library chain instead of replacing the trap the caller set. The process reaper reports a `/proc` read failure instead of returning "nothing to reap".
- **Verification.** The gated runners' post-suite sentinel check no longer reports a project HALT written by the chain's own release script as a test leak. A dashboard test no longer leaves `status-bottom-loop.sh` running after teardown. Three verify scripts and several unit tests that could not fail, or never ran on the host, assert what they claim. Dev-tree path resolution honours the documented fallback chain in every reader, not three of ten.
- **Messages and comments.** The wake's resume log line and the comments describing the resume modes name the stale-active sweep as a writer. Stale citations of scripts, flags and files that no longer exist were removed from the operations guide, the API reference, the projects-registry reference and code comments; the cost-report flag table is complete and `upgrade.sh --no-backup` is documented.
- **OVERWATCH and the remote.** With `push_to_remote = false` the push-lag check contacts no remote at all; before, it listed the remote's tags on every sweep. With pushing on, a remote that cannot be read is recorded as one `remote-unreachable` row and nothing is pushed, instead of every tag being counted as unpushed and a push attempted. The orphan-branch and empty-files checks no longer silence a finding when the bug deposit fails: the "reported" marker and the quarantine rename happen only after the bug exists.
- **Action log.** Every writer of `overwatch/actions.log` (the shell logger, the revert script, the temp-litter report and the Python resolution stage) flattens tabs, carriage returns and newlines in all six fields, so a multi-line git error or an odd file name is one record, not two lines or a seventh field. The shell and Python flatteners now produce the same text for a value that mixes a non-ASCII space with a tab or line break. The dashboard's reader splits records on newlines only and no longer drops records the writers wrote correctly.
- **Temp-litter report.** The `rm -f` remedy quotes every entry path, so a name with a space, dash or newline removes exactly that entry; the status section and the log line flatten entry names, so a name cannot plant a heading in `status.md`; the header states which outputs carry the remedy. A pre-existing `/tmp` entry whose name contains a line feed is no longer reported as session litter when it changes, and an entry whose name starts with a dot is reported like any other. The OVERWATCH litter check now finds the snapshots the wake writes before dispatch, instead of logging that no snapshot exists on every sweep, and reads line-feed names and dot-entries the same way the report does.
- **Dashboard processes.** Cadence panes no longer leak one `bash` process per refresh, and pane teardown no longer leaves the `sleep` child or the stream renderer's group behind; the status band leaves no orphan. Every command the dashboard types into an interactive shell ends with the comment `# pgai-agent-kanban-dashboard`, so your shell history tells its lines from yours. The geometry check finds the queues pane whatever the width of the PID column, and a resize that degrades the board shows its notice on screen instead of only in a tmux option.
- **Containers.** Every container the kanban starts (`container-up.sh`, `container-shell.sh`, the stranger's-path harness and the three-host matrix) runs with `--init`, so PID 1 reaps exited processes and a long-running container cannot fill the host with zombies. Tests that build images or start containers are gated on the operator container tier inside the test files themselves, so no agent wake ever runs a build.
- **CM wake failure paths.** The post-ship steps that could only warn to stderr and continue (the auto-ship line, the auto-ship event, the unverified-ship note, the measured-pace and metrics-rollup refreshes with a missing helper) now write an operator-inbox entry naming what was not done and the command that does it.
- **Wake, reaper and budgets.** A `/proc` read failure during process reaping reaches the inbox and the attention pane instead of only the wake log, and its streak counter is updated under a lock. A stale-active sweep that cannot count a branch's unmerged commits no longer records that branch for resume. A per-task timeout with committed work whose requeue budget cannot be read requeues once instead of blocking the lane. The workflow dispatcher finds its workflows directory in an installed layout without `PGAI_AGENT_KANBAN_ROOT_PATH` set.
- **Install and upgrade.** `install.sh --add-codex-agents` adds the codex wrappers whether or not `[providers] available` names codex, as `upgrade.sh` already did, and says so.
- **Project registry.** The next free priority and the next free dashboard colour are computed from project sections only, so a `[defaults]` section cannot raise the priority and a non-numeric priority cannot hand two projects the same colour.
- **Tests that could not run or could not fail.** Two board-geometry tests no longer race tmux in the gated run, the quarantine-visibility test passes when the checkout's own path contains the dev-tree name, a lock-wait test no longer fails on timer rounding under host load, the dashboard cadence test fails for the regression it exists to catch, and a configuration-loader test no longer depends on the Python package being reachable beside the loader.

## Reliability

- Fourteen groups of duplicated Python function bodies and seven pasted bash blocks (help preludes, OVERWATCH check preambles, test-runner flag handling, verify harnesses, root walk-ups, config-load fallbacks) are shared from one definition each; the duplicate lint's allowlist is empty.
- Shipped scripts and library functions that nothing ran were removed.
- The provider skill home is computed in one place, used by the install verb, the upgrade and the REST route.
- The non-blocking docstring-coverage lint reports nothing.
- Every Python file is written to Python 3.12 idioms (`X | None` unions, builtin generics, `datetime.UTC`, PEP 695 type parameters) and formatted with black at 120 columns. No behaviour change. Test helpers that scrub `PATH` now put the running interpreter first, so scripts run under the same Python as the suite.
- One definition each for the release-hook timeout default, the board `rows_per_column` default, the dev-tree path fallback chain, the "destination holds every source file byte-identical" comparison, the token-aggregation helpers (one UTC-day bucketing rule), the wake entry scripts for both providers, the test-runner flag parsing, and the colour table and `info`/`ok`/`warn`/`err`/`die` loggers; the shared-blocks lint also scans the repository-root scripts and multi-line definitions. The bash semver and registry readers that re-implemented Python modules were removed in favour of calling them.
- Shipped fixtures and docstrings carry no operator handle and no sibling project's name; the hygiene lint scans the test tree so neither can return. The two shipped operator skills are asserted byte-identical by a test. Every executable script, including the container entrypoint and the migrations, answers `--help`.
- The bash and Python last-released resolvers are pinned to the same fallback order by a unit test, and the legacy `PROJECT.cfg` loader is covered by tests for stale values, exported scratch variables and a failing line.

- The release reference and the CM role file give the same count of system-breaking finding classes.
- CODER, PM and TESTER role files, the bug template and the test-authoring guidelines say where a test goes: the module's existing test file, parametrised rather than duplicated; a new test file only for a new source module; acceptance names the behaviour, not a test to add.

The core SOP's remote rule names those two checks beside CM.
- The core SOP names the only readers of a project's dev tree: the release scripts and OVERWATCH's reconcile checks, the last-released resolver, install and upgrade, the test runners and deep-verify, and the dashboard git panes; every one of them resolves the tree through the project's `dev_tree_path` and degrades to a stated skip when it is absent. - Every statement of where the last-released version comes from matches the resolver: release tags merged into the project's remote prefixed main branch, then the local prefixed main branch, then all local tags carrying the prefix, then `release-state.md`. The OVERWATCH role file says where the litter check's session snapshots come from.
- The operations guide cites installed paths (`$KANBAN_ROOT/scripts/...`) throughout, its `kanban-status.sh` commands name a project and run as printed, and its CM HALT-trigger table lists the release-hook runner keys. The release reference counts the six cold-lane test modules. The roadmap names the current public release and the disk-hygiene guide shows the current task-ID format. The dashboard documents say the panes run under `cadence-loop.sh`, not `watch`, and name the pane each renderer runs in; the dashboard guide explains the history tag on typed commands.
- The TESTER role file states that a defect noticed outside the release candidate's scope is filed as a pre-existing bug, one per file, and that `## Suggestions` holds enhancements only. The CM role file's ship-matrix rows write operator-inbox entries where they used to say "file a bug"; CM files no bugs.

## Operator-facing changes

- `scripts/install-skills.sh` is new (`--list`, `--json`, `--dry-run`, `--force`, `--dir`, `--provider`, `--claude-home`, `--codex-home`). Exit `0` installed or already the same, `1` a write failed, `2` usage error, `3` a changed skill was left alone because `--force` was not given.
- `install.sh` and `upgrade.sh` deposit the shipped skills into `skills/<provider>/<name>/` under the kanban root and record them in `.installed-skills`; skills you add there are never written, renamed or deleted. `upgrade.sh --add-claude-skills` and `--add-codex-skills` run the install verb after the deposit. The codex flags now act, and say so, whether or not `[providers] available` names `codex`.
- `scripts/reset.sh --discard-branch` is new; the default keeps an unmerged feature branch.
- `GET /skills` is a new read-only REST route.
- The operator window's workbench shell and command-line shell are where you run operator verbs; `scripts/dashboard/suggested-commands.sh` prints a reminder of the common ones.
- `scripts/container-up.sh` and `scripts/container-shell.sh` start containers with `--init`. If you start the shipped image by hand, pass `--init` too.
- Lines the dashboard types into your shells carry the trailing comment `# pgai-agent-kanban-dashboard`; `history | grep -v ' # pgai-agent-kanban-dashboard$'` shows only what you typed.
- A project's dev tree may be moved or absent while the kanban runs other projects; the verbs that need it (release, upgrade, the test runners, deep-verify, the dashboard git panes) say so and stop, nothing else notices. Keep `dev_tree_path` in each project's `project.cfg` current.

## Breaking changes / upgrade notes

- **Python 3.12 or newer is required** to run any kanban script, as the package's `requires-python` already declared. An older `python3` on `PATH` now fails at import time with a syntax error.
- Upgrade with `scripts/upgrade.sh v3.5.0 --force --add-claude-agents --add-codex-agents`, adding `--add-claude-skills` and `--add-codex-skills` to install the shipped skills into the provider CLI homes. Role files changed, so the agent flags are needed to refresh the installed role wrappers. The crontab is unchanged; it does not need reinstalling.
- The dashboard session must be recreated for the new operator window (`scripts/dashboard/create.sh`).
- **New keys in `kanban.cfg`, all optional, with their defaults:**
  - `[dashboard] operator_workbench_pct = 40`, `operator_workbench_min_cols = 160`, `operator_board_agents = merged` (`merged` | `split`), `status_max_width = 320`, `arm_timeout_seconds = 20`.
  - `[discovery]` is a new section: `settle_seconds = 60`, `reject_threshold = 3`.
  - `[cleanup] task_retention_days = 7`.
  - `[verify] deep_verify_freshness_window_days = 7`.
  - `[release] hook_timeout_seconds = 900`. A hook is never unbounded: a value that is not a positive whole number is warned about and the default applies. Read from `kanban.cfg` only, not `project.cfg`.
  - `[overwatch] verb_timeout_seconds = 3600`. Keep it above what a release takes with up to three hooks. Read from `kanban.cfg` only.
  - The example values of `[governance] budget_bytes_coder` and `budget_bytes_po` are both raised to 81920, for the larger CODER role file and the larger shared core text; raise yours if the governance byte-budget lint reports a role over budget.
- **Environment variables now have config keys.** `PGAI_DISCOVERY_SETTLE_SECONDS`, `PGAI_DISCOVERY_REJECT_THRESHOLD`, `PGAI_CLEANUP_TASK_RETENTION_DAYS`, `PGAI_DEEP_VERIFY_FRESHNESS_WINDOW_DAYS`, `PGAI_DASHBOARD_STATUS_MAX_WIDTH` and `PGAI_DASHBOARD_ARM_TIMEOUT_SECONDS` still win when set; move the values into `kanban.cfg` and unset them.
- **`[dashboard] rows_per_column` is honoured.** A dashboard that relied on the old hard-coded 13 rows now renders 21 by default; set the key to keep 13.
- **Behaviour changes with no opt-in.** `reset.sh` and the stale-active sweep keep an unmerged feature branch; pass `--discard-branch` to a reset when the work is not wanted. Release hooks and OVERWATCH verbs are killed at their time limits. `[wake] max_runtime_seconds = 0` now means no batch bound. A project whose dev tree holds no prefixed release tag now reports the version in its `release-state.md` instead of `v0.0.0`.
- **`project.cfg`:** no keys added, renamed or removed.
- **New runtime files.** `skills/<provider>/<name>/` and `.installed-skills` under the kanban root. Nothing to configure.
