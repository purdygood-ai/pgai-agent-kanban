# team/config/doc-command-truth-help-exempt.txt
#
# Exempt list for the HELP FAILS check in
# team/scripts/lint_doc_command_truth.py (the doc-truth lint's
# command-existence half).
#
# Entry criterion: a path belongs here ONLY when every document citation
# that resolves to it is process-internal — the file is named so a reader
# can find it, never so a reader can run it as an operator command line
# (a sourced prelude, a container entrypoint, or the equivalent). It does
# NOT belong here because a --help fix is merely inconvenient to write; an
# operator-facing script that genuinely owes a --help (coding-standards
# directive 6) gets the --help, not an entry on this list. Compare
# team/scripts/help_presence_exempt.txt, which draws the identical
# distinction for the help-presence lint's own "process-internal" category.
#
# Format: one repo-root-relative path per line (matched against the
# citation's *resolved* file path — not the literal text a document used
# to cite it, so a bare-basename citation and a full-path citation of the
# same file are treated identically). Blank lines and `#` comments are
# ignored. Every entry must carry a reason as a comment on the line(s)
# immediately above it — a bare list of paths with no reasons reproduces
# the untracked-finding problem this list exists to close, one layer down.
#
# What this list does NOT do: it never exempts a path from the existence
# half of the check. A listed path whose file is deleted or renamed still
# fails to resolve and still produces a MISSING COMMAND finding — the
# exempt-list lookup in lint_doc_command_truth.py only ever runs after
# resolution has already succeeded.
#
