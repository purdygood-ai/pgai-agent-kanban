# team/config/operator_verb_census_exempt.txt
#
# Exempt list for team/scripts/lint_api_parity.py's census-walk gate
# (check_app_routes_have_census_row / class 2, and
# check_scripts_have_census_row / class 4) and for
# team/scripts/lint_operator_verb_manifest.py's route-coverage check (check
# 6). team/config/operator_verbs.manifest
# is the single source of truth for the operator VERB estate the REST-parity
# contract scopes -- it is deliberately narrower
# than "every script under team/scripts/ that declares OPERATOR_VALID_FLAGS"
# (class 4) or "every script any router shells out to" (class 2), per
# lint_operator_verb_manifest.py's own check_operations_reverse docstring
# ("reads.py fronts a much wider set of read-only convenience endpoints ...
# not part of the operator VERB set this manifest catalogues"). This sidecar
# is how that narrower scope stays a documented, checked-in fact instead of
# an unwritten exception a filesystem scan would otherwise flag as drift.
#
# Format: one entry per line, in either of two forms. Blank lines and `#`
# comments are ignored. Every entry must carry a reason as a comment on the
# line(s) immediately above it.
#
#   Script entry -- a script BASENAME (e.g. "show-readme.sh" -- never the
#   "scripts/..." relative form, since class 2's fronted-script detection and
#   the manifest's own check_operations_reverse precedent both key on
#   basename, and every script this list names has a unique basename across
#   the tree). lint_api_parity.py's classes 2 and 4 read these.
#
#   Route entry -- an HTTP method, whitespace, and the route path exactly as
#   the API registers it, router prefix included and path parameters as
#   declared (e.g. "GET /board", "GET /traces/{trace_id}"). Check 6 of
#   lint_operator_verb_manifest.py requires every registered route to be
#   either the REST twin of a manifest row or named by a route entry, and
#   reports a route entry whose route the API does not register, that a
#   manifest row already twins, that is repeated, or whose line directly
#   above is not a reason comment. A script entry never covers a route,
#   even the route that reads what the script prints: each such route
#   carries its own route entry beside the script's. A route entry exempts
#   no script -- it can never equal a basename, so lint_api_parity.py's
#   classes read it as a no-op.
#
# What this list does NOT do: it never removes a script from the operator
# verb estate the REST-parity contract itself names (why, show,
# show-queues, rc-metrics, agent-metrics, release-state, deep-verify,
# halt/unhalt family, defer/undefer, wake-now, intake, release-locks,
# unwind-rc, cancel-rc, deep-verify) -- every one of those carries a census
# row, and an entry here for one of them (release-locks.sh, below) exists
# only because that verb has a SECOND route for a second mode, and the
# manifest carries exactly one REST twin per row: the entry documents the
# extra route, it does not stand in for the row. Backfilling a script
# listed below into a real census row (or removing it here because it
# never fronts an operator verb) is future work; this list makes the
# current, deliberate gap visible rather than silently flagged as noise on
# every run.
#
