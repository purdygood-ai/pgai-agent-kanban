# Gate/Lint Remedy Census — v1.27.2

## Purpose

This census enumerates the full deterministic gate/lint fleet in the
pgai-agent-kanban tree and classifies each gate's **remedy obligation** — how
completely the gate can prescribe its own fix on failure. It scopes the
"gates prescribe, not just diagnose" retrofit and satisfies acceptance
criterion 3 of `PRIORITY-0001-gates-prescribe-remedies` ("Census artifact
ships; every gate classified; zero unclassified").

This is a tracking/audit document, not code. It classifies what a compliant
gate *could* prescribe; it does not assert that every gate already prints a
full remedy block today. Closing the gap between the classification and each
gate's current output is the retrofit this census scopes.

## Classification vocabulary

The three classes are defined by `docs/coding-standards.md`
("Gates prescribe, not just diagnose"):

- **full-remedy** — The fix is fully knowable at detection time and
  expressible as gate-derived, verbatim-runnable commands (house placeholder
  law applies: the gate substitutes the site-specific literals it already
  resolved). A stranger reading only the failure output can clear the gate
  with no other guidance.
- **partial** — The gate can name the exact cause and location and prescribe
  the *shape* of the fix, but the terminal step is a genuinely free-form slot
  only a human can author (help text, a corrected link target, a rewritten
  function, a config value, a chosen identifier). The gate prints a
  filled-in example for the slot; it cannot emit the final literal.
- **non-deterministic (exempt)** — The fix is not knowable at detection time
  (a real test/assertion failure, a project-supplied hook failure, a merge
  divergence, a provider/network fault, a ship-policy judgment). Exempt from
  the numbered command block, but **never** exempt from naming the next
  diagnostic step — the specific evidence to read next.

Every entry below carries exactly one class. Every non-deterministic (exempt)
entry carries a one-line justification.

## Segment A — Standalone Python lints

### 1. CHANGELOG freshness — full-remedy
**Source:** `team/scripts/lint_changelog_freshness.py`
Regenerates `CHANGELOG.md` from the current codebase and byte-compares against
the checked-in artifact; a stale or missing artifact fails. The clearing
command (regenerate via the changelog writer, then commit) is fully computable
at detection time. The motivating case for the retrofit. **Retrofit note:** the
house-placeholder-law fix landed in this RC (CODER-20260727-016). The remedy
block now carries no angle-bracket placeholders — the failure text derives
literal paths at detection time and routes the regenerate command through
`pp_run_ops.sh`.

### 2. Comment provenance — full-remedy
**Source:** `team/scripts/lint_comment_provenance.py`
The seed pattern named by the standard. On a finding it prints the offending
`file:line`, the exact token, the one-line rule, and the precise way to clear
it (remove the token, move it to commit/task state, or add the verbatim
per-line opt-out). The clearing action is gate-emittable, so full-remedy.

### 3. ICD freshness — full-remedy
**Source:** `team/scripts/lint_icd_freshness.py`
Regenerates the ICD to a temp file and byte-compares against the checked-in
artifact. The clearing command (`bash team/scripts/generate-icd.sh` then
commit) is fully derived. Same freshness shape as row 1.

### 4. Upgrade no-temp-copy guard — full-remedy
**Source:** `team/scripts/lint_upgrade_no_temp_copy_guard.py`
Fails when forbidden lines appear in the upgrade script's pre-retirement
block. The gate names the exact offending lines; the remedy is to remove those
named lines and re-run. Removal authors no new content, so the fix is fully
prescribable.

### 5. Help presence (Directive 6) — partial
**Source:** `team/scripts/lint_help_presence.py`
Fails when a script lacks a `--help`/`-h` handler. The gate names each
offending script and prescribes the action (add a `--help` handler, or add the
basename to the exempt list). Adding the exempt entry is verbatim, but
authoring the `--help` body — text describing every argument — is free-form
content only the author can write.

### 6. Python import completeness — partial
**Source:** `team/scripts/lint_python_import_completeness.py`
Fails when a third-party import is not covered by `requirements*.txt`. Names
the missing module and its source file. When the pip package name equals the
import name the append is prescribable, but the differing-name case
(the reason `_PACKAGE_TO_IMPORT_NAMES` exists) requires a human-supplied pip
package name the gate cannot always resolve.

### 7. Dashboard network-git gate — partial
**Source:** `team/scripts/lint_dashboard_network_git_gate.py`
Fails on any network-capable git verb (`ls-remote`, `fetch`, `pull`, `push`,
`clone`) under `team/scripts/dashboard/`. Names `path:line`, the verb, and the
rule. The fix — replace the call with a local-only equivalent — is authored
code, not a derivable command.

### 8. API parity — partial
**Source:** `team/scripts/lint_api_parity.py`
Fails when an API model is missing an expected field. Names the missing field
and the model to add it to. The field's type and definition are author
content.

### 9. Env-bootstrap ordering — partial
**Source:** `team/scripts/lint_env_bootstrap.py`
Fails when a script accesses the kanban-root env var outside the canonical
resolver, or sources the bootstrap prelude after its first non-comment env
reference. Names `file:line` and the exact import to use
(`resolve_kanban_root` from `pgai_agent_kanban.env`). The corrective
re-ordering/rewrite is authored code.

### 10. ICD compatibility — partial
**Source:** `team/scripts/lint_icd_compat.py`
Fails when the current ICD breaks compatibility with a SUPPORTED baseline (or a
manifest/baseline is missing or unparseable). Names the offending version and
field. The resolution — restore the contract or widen the supported set — is a
design decision only a human makes.

### 11. Lib-function dedupe — partial
**Source:** `team/scripts/lint_lib_function_dedupe.py`
Fails on a duplicate function definition under `team/scripts/lib/`. Names the
duplicated function and both locations; prescribes "remove or rename the
duplicate, or add to the allowlist." Which copy survives (and any rename) is
author judgment.

### 12. Orphan tests — partial
**Source:** `team/scripts/lint_orphan_tests.py`
Fails when a `test_*.py` file is unreachable from any collected test root.
Names the orphan file and prescribes "add it to a collected root or extend a
glob." Where to wire the test is author judgment.

### 13. Test anti-patterns — partial
**Source:** `team/scripts/lint_test_anti_patterns.py`
Fails when a test uses a banned pattern (e.g. bare `/tmp`). Names `file:line`
and the sanctioned idiom (`source team/scripts/lib/temp.sh` and use
`$(pgai_mktemp PREFIX)` / `$(pgai_mktemp_d PREFIX)`). The surrounding rewrite
to that idiom is authored code.

## Segment B — Standalone bash gates

### 14. Skip-cites-real-bug gate — partial
**Source:** `team/scripts/lint_skip_bug_gate.sh`
Two failure classes: (a) placeholder skip citations in test files, and (b)
cited `BUG-NNNN` IDs with no matching file in `bugs/`. Names the offending
lines and IDs. The terminal fix — supply the real bug ID, or file the missing
bug report — is author content the gate cannot know.

### 15. Per-project dev-tree verify gate — non-deterministic (exempt)
**Source:** `team/scripts/verify-perproject-devtree-gate.sh`
**Justification:** it is a behavioral verification fixture (D3) whose pass/fail
assertions exercise runtime per-project dev-tree resolution; an assertion
failure's fix depends on why the observed behavior diverged and is not
computable at detection — the gate names the failing assertion (and its
embedded `bash -n` syntax check names the offending file) as the next step.

## Segment C — doc-lint harness failure classes

The harness (`team/scripts/harness/doc-lint.sh`) runs one of four suites; each
suite is a distinct gate with its own remedy obligation.

### 16. cmd suite — non-deterministic (exempt)
**Source:** `team/scripts/harness/doc-lint.sh`
**Justification:** it executes fenced documented commands verbatim; a non-zero
exit can arise from a stale command, a missing skip annotation, or absent
external state — the correct resolution is not computable at detection, so the
suite names the file, the command text, and the exit code as the next
diagnostic step (and documents the three skip mechanisms).

### 17. links suite — partial
**Source:** `team/scripts/harness/doc-lint.sh`
Fails when a relative Markdown link does not resolve. Names the file and the
broken target. The corrected target path is the author's intended destination,
which the gate cannot infer.

### 18. fossil-greps suite — partial
**Source:** `team/scripts/harness/doc-lint.sh`
Zero-hit gate: any match of a known internal-residue pattern fails. Names
`file:line` and the matched pattern. Removing the residue is prescribable in
shape, but the surrounding rewrite is author content.

### 19. feature-greps suite — partial
**Source:** `team/scripts/harness/doc-lint.sh`
Must-find gate: a required feature token missing from all audited docs fails.
Names the missing token. The fix — author the documentation section that
introduces the token — is free-form content.

## Segment D — Release script (release.sh) deterministic gates

All gates in `team/scripts/cm/release.sh` run before the destructive squash
("verify before destroy"). A firing gate writes `HALT` and exits without
shipping, except the post-tag hook (row 26), which is non-blocking.

### 20. pre-squash hook gate — non-deterministic (exempt)
**Justification:** the pre-squash hook is project-supplied; a non-zero exit's
fix lives in the hook's own output, not in the release script — it points the
reader to the `[hook cm-release-pre-squash]` lines above.

### 21. placeholder-stamp guard — partial
**Source:** `team/scripts/cm/release.sh`
Fires when the `PENDING-RELEASE` placeholder survives the stamp step, or no
recognizable `## Status` line is found in the release notes. Names the notes
file and the expected `## Status` / `PENDING-RELEASE` shape; the corrective
edit to malformed notes is author content.

### 22. fidelity gate — non-deterministic (exempt)
**Justification:** it fires when the RC tree diverges from the main branch
after the squash (an out-of-band commit landed on main mid-RC); reconciling
the divergence is operator judgment, so the gate prints `git diff --stat` of
the divergent paths as the next step rather than a command.

### 23. squash-pollution guard — non-deterministic (exempt)
**Justification:** in strict mode it lists paths that polluted the squash and
HALTs; why the pollution appeared, and whether each path is legitimate, is a
judgment the gate cannot compute — it lists the concrete paths as the
starting evidence.

### 24. pre-tag hook gate — non-deterministic (exempt)
**Justification:** the pre-tag hook is project-supplied; like the pre-squash
hook its failure is resolved from the hook's own captured output
(`[hook cm-release-pre-tag]` lines), which the release script cannot turn into
a verbatim command.

### 25. pre-tag VERSION gate — full-remedy
**Source:** `team/scripts/cm/release.sh`
Fires when the on-disk `VERSION` does not equal the tag about to be cut. The
gate knows both the current value and the required version, so it can
prescribe the exact corrective write (set `VERSION` to the derived release
version, commit, re-run).

### 26. post-tag hook (non-blocking) — non-deterministic (exempt)
**Justification:** the post-tag hook runs after the tag exists; its failure is
a logged warning only and cannot roll the release back — it is a
project-supplied hook whose failure is diagnosed from its own output, and it
does not veto the release.

### 27. ship-policy HALT triggers — non-deterministic (exempt)
**Justification:** the ship-policy matrix HALTs on TESTER-state BLOCKED,
systemic-risk high, a large-fix-effort finding, or the
last-3-RCs-NON-FUNCTIONAL pattern; these are release judgments derived from the
TESTER report, not conditions a command clears — the operator reads the TESTER
report named in the HALT reason.

### 28. UU merge-conflict HALT (Trigger 5) — non-deterministic (exempt)
**Justification:** an unresolvable content (UU) conflict during the squash has
no gate-derivable fix; the operator must resolve the named conflicting paths by
hand, which the release script must not auto-resolve.

## Segment E — Gated-runner pre-flight aborts and post-suite assertions

Hosted in `team/scripts/run-unit-tests.sh`, `run-integration-tests.sh`, and
`run-gated-tests.sh` (some via shared helpers). Each runner also invokes the
Segment A/B lints as pre-flight; those are classified at their own source
files.

### 29. env-bootstrap source abort — partial
**Source:** all three runners (`source .../lib/env_bootstrap.sh || exit 1`)
Aborts when the env-bootstrap prelude cannot be located or sourced. The abort
names the failure; the corrective — supply the missing/unreadable env file or
fix the invocation environment — is site-specific operator input the runner
cannot resolve.

### 30. `require_dev_tree` pre-flight abort — partial
**Source:** `team/scripts/lib/dev_tree.sh` (invoked by all three runners)
Aborts with "dev_tree_path not configured in kanban.cfg" or "does not exist."
Names the exact config key and the resolution context; the path value the
operator must supply is a site-specific free-form slot.

### 31. pytest-not-installed abort — full-remedy
**Source:** all three runners
Aborts (exit 2) with the verbatim clearing command: `pip install pytest`. The
fix is fully prescribed.

### 32. unknown-argument abort — partial
**Source:** all three runners
Aborts (exit 1) naming the unrecognized argument. The correct invocation is
recoverable from each runner's `--help`, but which valid flag the operator
intended is user intent the runner cannot supply.

### 33. pytest test-suite failure — non-deterministic (exempt)
**Justification:** a real assertion failure ("Unit/Integration/Docker-gated
tests FAILED") has no verbatim fix; the runner points the reader to the pytest
tail printed above (the failing file and assertion) as the next diagnostic
step.

### 34. bare-/tmp cleanliness assertion — non-deterministic (exempt)
**Justification:** the post-suite check fails when the suite left residue in
bare `/tmp`; identifying which test bypassed the temp resolver requires
investigation the check cannot compute — it reports the residue as the
starting evidence.

### 35. TCP listener cleanliness assertion — non-deterministic (exempt)
**Justification:** the post-suite check fails when a framework-rooted TCP
listener survived the suite; which test leaked the listener is not computable
at detection — the check reports the surviving listener (scoped to this
project's temp subtree) as the next thing to investigate.
